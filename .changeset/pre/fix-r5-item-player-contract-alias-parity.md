**Breaking: the facade's PnP profile and PCI host-trust family are now exact aliases of the item-player contract types** (beta prerelease), finishing the round-4 de-mirroring that stopped halfway. `QtiPnpProfile` is `@pie-qti/item-player`'s `PnpProfile` — it gains the fields the hand mirror had already dropped (`display.structuredLabelSupport`, `cognitive.spellChecker`), `display.colorScheme` narrows from any string to the AfA/QTI3 named schemes the player actually renders (a host passing an arbitrary colorScheme string must now use a named one), and `content.catalogSupports` takes the structured `CatalogSupportPreferences` shape. `QtiPciHostConfiguration` keeps its round-4 name (item-player's `QtiPciConfiguration` is the unrelated module-facing contract) but is now exactly `PciConfiguration`; `QtiPciModuleResolver`, `QtiPciModuleResolutionContext` and `QtiPciModulePathKind` are 1:1 aliases of the root-exported upstream types, and `QtiPciSandboxConfiguration`/`QtiPciModulePolicy` alias item-player's `./pci` entry, which exports them at their own names. The shapes were already field-identical, so only `QtiPnpProfile`'s members change. New drift pins in `tests/data-model-contracts.ts` (identity `Exactly` pins plus a source walk) fail the build if any of the seven names regresses to a hand copy or a drifted alias.
