Five message keys referenced by player components existed in no catalog, so their hardcoded English fallbacks rendered in all seven non-English locales. They are now translated in every framework catalog (en, fr, es, nl, ro, th, ar, zh-Hans): `assessment.feedback.title` (feedback dialog title), `interaction.renderError` (screen-reader announcement when an interaction cannot be rendered; safety-relevant — best-effort translations in th/ar are marked for native-speaker review in the catalogs), `interactions.hottext.minimumMet` and `interactions.hottext.selectAtLeast` (hottext minimum-selection badges; the value carries no checkmark because the component renders its own), and `customInteraction.portableLabel` (Portable Custom Interaction group label). Locale catalogs now carry 896 keys each, up from 891.

`check:i18n` can now see this defect class. `check-translations` compares interpolation placeholder names against en for every key a locale carries (plural leaves may omit them, for locales that spell small counts out as words — the documented ro/ar `.one` forms). A new `check-consumer-keys` scan walks `packages/<pkg>/src` and `apps/<app>/src` and fails when a literal key passed to `t()`, `translate()`, `translatePlural()`, `.plural()` or named in a `labelKey` exists in neither the framework en catalog nor a registered host custom-messages catalog (the demo app's `demo-messages.ts` is registered); it runs as the second step of `check:i18n`. `translate()`/`translatePlural()` keep accepting string keys — the doc comments now state where literal-key correctness is enforced.
